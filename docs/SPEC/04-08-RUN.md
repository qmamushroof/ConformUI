## 4.8.2 Procedure (`SPEC-RUN-01`, PRD-F-04.1..04.5, PRD-F-08.2)

1. Load the active Contract (accepted Requirements only) and current captures. Viewports in the Run = viewports with a capture (PRD-F-08.2); Requirements for other viewports → `not-checked no-capture`. A viewport with a capture, no design and no Inferred items in the Contract gets one result `not-checked no-inferred-items` with hint "Re-open contract" (Inferred items are generated only by `ContractService`, `SPEC-CON-04`; Run never calls `infer-responsive`).
2. Per viewport (`MeasureClient`, main thread, S22): load pixels, `align` (`SPEC-MEAS-05`), run **Measured** then **Visual** handlers (§4.8.3). Each stage = one `TraceStep` (`engine:'measured'`, `bytesSent:0`).
3. **Judged** stage, per viewport: if `status.deviceImage !== true` and the viewport has a DOM snapshot → `resolveMode({ purpose:'first-pass', needsImage:false })` and a **text-only** `judge` from DOM data and measurements (confidence capped Medium, PRD §7 text-only); otherwise `needsImage:true` and an image `judge` with one `ImageCodec.composePair` image (`SPEC-AI-11`; on-device it is letterboxed and both crops carry context, evidence regions stay the exact ones). The judge prompt tells the model that grey bars are padding and to answer `uncertain` rather than `pass` when it cannot compare. `call` → one request per Judged item. `blocked` → `not-checked` with its reason. `needs-consent`: on a normal Project emit `needs-consent` once per Run (`resume(null)` → `not-checked consent-declined`); on a **sample** Project no modal opens: precomputed Judged results are used (`SPEC-RUN-13`). Deterministic results are kept whatever happens here.
4. Severity, confidence, Findings from deterministic templates (`SPEC-RUN-07`), Re-verify comparison (`baselineRunId` = newest earlier Run with the same `contractId`), `store.putRun(run)`, then `store.putContract(lockContract(contract))` (`SPEC-KERNEL-11`, `SPEC-CON-06`). Thresholds snapshot stored in `run.thresholds`.

`SPEC-RUN-02`: one Run at a time per Project; Abort keeps completed results as a partial Run marked "Stopped". Any thrown handler error → that Requirement `not-checked` with reason, Run continues (PRD-P-09).

`SPEC-RUN-13` (sample, PRD-M-13, PRD-D-22): when a sample Project's Judged stage is `needs-consent` or `blocked`, Judged items take `PrecomputedJudged.flawed`/`fixed` (chosen by which capture set is loaded), results get `origin:'precomputed'`, `run.precomputed = true`, the Run banner says "Sample results (pre-computed)" and offers a non-blocking action **Allow cloud to judge live** (opens the consent sheet; on Allow, `rejudge` re-runs only the Judged stage and replaces the precomputed items).

## 4.8.3 Check handlers (`SPEC-RUN-03`; `Requirement.checkType` selects the path, `CheckSpec.kind` the handler)

| Kind | `checkType` | Path with DOM snapshot (`dom-snapshot`, High) | Path without DOM | Fail severity (explicit) |
|---|---|---|---|---|
| `presence` | `visual` | **always** `SPEC-MEAS-10` ink test at the located rect (Medium), DOM ignored | same | Critical |
| `presence` | `measured` | ≥ 1 visible match in region (scaled) | ink test, Medium | Critical |
| `count` | `measured` | visible matches = `expected` | Judged (crop + expected), ≤ Medium | Major |
| `text` | `measured` | normalised text contains `expected` | Judged, ≤ Medium | Major |
| `size` | `measured` | DOM box vs snapped design rect; \|pct\| ≤ `size_tolerance_pct` pass | locate + snap on capture, Medium | ≥ `major_deviation_pct` Major, else Minor |
| `spacing` | `measured` | gap a→b vs design gap (`aRect`,`bRect`); \|pct\| ≤ `spacing_tolerance_pct` pass | snap both on capture, Low → Needs review | \|pct\| ≥ 2× `major_deviation_pct` Major, else Minor |
| `dominant-text` | `measured` | match `fontSize` ≥ the `fontSize` of every other visible element of kind heading/text/link/button with non-empty `text` or `name` | Judged, ≤ Medium | Major |
| `colour` | `measured` | DOM colour vs design ΔE (`SPEC-MEAS-11`) | Judged, ≤ Medium | ΔE > 3× threshold Major, else Minor |
| `layout-fits` | `measured` | fails if `horizontalPx > 0`, any overlap, or any clipped text (`SPEC-MEAS-13`); one Finding listing each fact | `not-checked no-dom-snapshot` | Major |
| `visible` | `measured` | match visible and not `beyondViewport` | `not-checked no-dom-snapshot` | Major |
| `region-diff` | `visual` | `regionDiff` at located rect; ratio > `visual_diff_ratio` fails, Medium | same | ratio ≥ 2× threshold Major, else Minor |
| `position`, `judged` | `judged` | AI `judge` (text-only variant when no device image, step 3): pass → Pass; fail + High → Fail; else Needs review | AI `judge` (image) | Major |

`SPEC-RUN-04`: an unresolved design region, a location score < 0.5, or misalignment for image handlers → `needs-review` (region issue) or `not-checked misaligned`; never a guessed number. P0 has no Measured position or image-path colour (S21).

## 4.8.4 Severity, confidence, status (`SPEC-RUN-05..06`, PRD-P-03, PRD-P-04, PRD-D-20)

- `SPEC-RUN-05`: severity by impact (table above), not pixel count. Rendering noise is excluded by `includeAA:false` and the ratio threshold.
- `SPEC-RUN-06`: `label:'inferred'` → severity `min(severity, minor)` and statements worded "Expected … (inferred)"; Low confidence → status `needs-review`. Tested: no Inferred Finding above Minor (PRD-M-10).

## 4.8.5 Findings (`SPEC-RUN-07`, PRD-F-05.1, PRD-F-05.2, PRD-P-07)

- A Finding exists for each `fail`/`needs-review` result and only for a Requirement (PRD-P-01). Evidence always has `designCrop` (design rect; for inferred items without a design viewport: none, then the capture crop of the matched/expected element) and `captureCrop` (Presence: the expected region on the capture). Missing both → status `needs-review` with "Evidence could not be produced" (PRD-P-07).
- Deterministic templates per kind give `statement`, `suggestedFix`, `condition`; e.g. size: "Primary CTA is 132 px wide vs 220 px in the design (−40.0%), measured from DOM snapshot." / fix "Make `<selector>` 220 px wide (or match the design's width rule)." / condition "`<selector>` width within ±8% of 220 px at a 1440 px viewport." AI `judge` text may replace `suggestedFix`/explanation only after `guardNumbers` passes (no separate explain call, S23).
- Each Finding records `engine` (`measured` for Measured/Visual, AI engine for Judged; Deep refinements set `refinedBy`) (PRD-P-06).

`SPEC-RUN-08` sort (PRD-F-05.3): severity (Critical → Minor), `fail` before `needs-review`, Explicit before Inferred, viewport (desktop, mobile), requirement id. [P1] filters by viewport, severity, label, status; [P1] dismiss as accepted deviation (excluded from Fix prompt, kept in report, PRD-F-05.5).

## 4.8.6 Re-verify (`SPEC-RUN-09..11`, PRD-F-07)

- `SPEC-RUN-09`: "Re-verify" = add/replace captures (+ optional snapshots) then `start` with the same Contract (PRD-F-07.1). "Run Re-verify" is disabled, with a visible reason, while every capture is one the base Run already checked; replacing any one viewport is enough. Finding statements name elements in words (text or tag), never a raw selector; selectors stay in the evidence and the fix.
- `SPEC-RUN-10` `compareRuns` per `reqId:viewport` (failing = fail or needs-review): prev failing → now pass = **resolved**; failing → failing = **remaining**; pass → failing = **regressed**; absent/not-checked → failing = **new**; pass → pass = **still-passing**; now not-checked → no change label. Summary line "6 resolved, 1 remaining" lists non-zero counts in the order resolved, remaining, new, regressed (PRD-F-07.2).
- `SPEC-RUN-11`: Run history lists date, contract version, viewports and pass/fail/review counts, newest first (PRD-F-07.3). [P1] compare any two Runs (PRD-F-07.4).

## 4.8.7 Engine trace (`SPEC-RUN-12`, PRD-F-04.5, PRD-D-17)

Every stage and AI call appends a `TraceStep` (`step`, `engine`, `durationMs`, `bytesSent`, `requestedMode`, `model`, `promptVersion`); the trace is stored with the Run and exported. For cloud steps, `app` updates `cloudUsage` (SPEC-APP-01). Deterministic stages and on-device calls report `bytesSent: 0`.

## 4.8.8 Acceptance tests

Sample (Node, committed contract, captures, snapshots; Judged via fake or precomputed): flawed Run → defects 1–6 `fail` with expected category/check type/severity, defect 7 `needs-review`, zero Critical/Major false positives (PRD-M-01); fixed Run vs flawed → 6 resolved, 1 remaining, 0 new/regressed (PRD-M-02); re-running unchanged → identical Measured/Visual statuses (PRD-M-09); every Measurement has source tags (PRD-M-03); consent declined → Judged `not-checked consent-declined` and zero cloud calls (PRD-M-06); sample Project with device unavailable → no modal, precomputed Judged items labelled, `run.precomputed` true (`SPEC-RUN-13`); text-only device + DOM → text-only judge with `needsImage:false`; Run on a viewport without Inferred items → `no-inferred-items` hint; contract locked via `lockContract` after save.
