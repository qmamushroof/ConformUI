# 9. Decisions

**[◀ 8. Deploy](08-DEPLOY.md)** · [SPEC index](../SPEC.md) · **[10. Traceability ▶](10-TRACEABILITY.md)**

SPEC decisions (`S#`, stable). They refine the PRD Decisions Log, never override it. A reversal edits the row and states the reason.

| # | Decision | Reason |
|---|---|---|
| S1 | **Mode mapping is computed by one pure kernel function** `resolveMode` and guarded again in the adapter (consent token required for any mode other than `ONLY_ON_DEVICE`; `ONLY_ON_DEVICE` only when the device is `available`). | PRD-D-18 must hold in every caller; two independent checks make a silent cloud call a tested impossibility (PRD-M-06). Also avoids `ONLY_ON_DEVICE`'s documented wait-for-download. |
| S2 | Keep the verified versions even where the registry has a newer patch (`@biomejs/biome` 2.6.8, `react-router` 8.5.2). | Verified as a compatible set on 2026-11-24; patch bumps arrive via Dependabot after CI passes. |
| S3 | TypeScript 6.0.3, not 7.x. | 7.x drops the JS compiler API that dependency-cruiser needs. |
| S4 | `PREFER_IN_CLOUD` is not used. | PRD-H-04 defines only `ONLY_ON_DEVICE`, `PREFER_ON_DEVICE`, `ONLY_IN_CLOUD`. |
| S5 | App Check provider = **reCAPTCHA Enterprise** (score-based Web key). | PRD-H-08 leaves v3/Enterprise to the SPEC; Enterprise has score-based keys and console-managed domains; v3 stays a one-line fallback (`ReCaptchaV3Provider`). |
| S6 | Deterministic engine split into `platform/imaging` (browser I/O) and pure `features/measure` (no DOM types). | Measure runs in Node tests on committed PNGs, in the page, in a later Worker, and later in an extension unchanged. |
| S7 | Model-proposed `expectedCount`/`expectedText` become Contract values only after the user accepts the Requirement; their source tag is `contract`. Sizes, positions, spacing and colours on the design side come only from snapped/user regions (`design-image`). | Keeps PRD-P-02 true: the model never supplies a displayed measurement; a count the user approved is a contract term, not a measurement. |
| S8 | Inferred requirements = one generic `layout-fits` Requirement per viewport + one `visible` item per explicit primary Requirement + optional AI proposals. Other explicit items are not copied to viewports without a design. | Responsive layouts legitimately hide or reflow elements; copying them would create false Inferred Findings, and one defect must map to one Finding (PRD-M-02 counts). |
| S9 | "Try the sample" opens with the verified sample Contract active (Run in one more click); Extract contract on the sample runs the real AI, is stored as a pending Contract and compared with the verified one; it becomes active only on "Use AI contract". | Satisfies PRD-M-13 (2 clicks) and PRD-F-10.5 (acceptance against the committed Contract) while still demoing on-device extraction and measuring PRD-M-14. |
| S10 | Theme follows `prefers-color-scheme`; no manual toggle. | Fewer states to test and keep accessible. |
| S11 | Judged requests send one side-by-side image (design left, implementation right). | On-device multi-image support is unverified (spike A2); one image is valid on every path. |
| S12 | Prompts are versioned files `prompts/<task>.v<N>.md` bundled with the app; Remote Config selects `N`. | Reproducible, diff-able prompts; no prompt text in public Remote Config. |
| S13 | No shared UI module. `EngineBadge`, `ConsentSheet`, `PrivacyCounter` live in `settings`; other features receive them as render props from `app`. | Keeps the allow-list table minimal (§3.2). |
| S14 | Each Run stores the threshold snapshot it used. | Same captures + same Contract → identical Measured/Visual results even after a Remote Config change (PRD-P-10). |
| S15 | `pixelmatch` 8.0.0 for pixel diffs; everything else (snapping, location, colour) is in-house TS. | Proven anti-aliasing detection (PRD-P-03) in a dependency-free ESM package; the rest is small and must be deterministic and explainable. |
| S16 | Images are stored once, normalised to CSS scale as PNG; AI crops are derived on demand as JPEG. | One coordinate system (CSS px) for DOM boxes, regions and pixels; lossless input for diffs; small AI payloads. |
| S17 | Cloud defaults as §4.1.6 (cheap first-pass model, stronger Deep model). On-device model is whatever Chrome ships. | Cheap first pass, stronger multi-image Deep Analysis; both changeable in Remote Config without redeploy (PRD-H-07). |
| S18 | Blocking CI: lint, types, architecture (incl. negative fixture), unit, build size, e2e. Advisory only: coverage (reported), Lighthouse (manual), test-title ID citations (no trace test). No deploy workflow: deploy and Remote Config publish are manual owner steps. | Fits the 25 agent-hour budget; nothing to operate in CI beyond tests. |
| S19 | Icon pipeline as `SPEC-PWA-01` (PRD-D-31); no custom icon script. | PRD-D-31; the padded mark (half-extent 21/64) stays inside the maskable safe circle. |
| S20 | Fix prompt includes Needs-review Findings marked "verify first". | The agent can confirm or fix uncertain items; excluding them would hide known risks. |
| S21 | P0 has no Measured position check and no image-path colour check: position is Judged; colour is Measured only with a DOM snapshot, else Judged. | Scope cut (25 agent-hours); both image paths are the least reliable and no planted defect needs them. |
| S22 | No measure Worker in release 1: `app` uses `inlineMeasureClient()` on the main thread; the async `MeasureClient` type stays so a Worker can be added later without API change. `SPEC-PERF-05` retired. | Region-limited pixel work fits the 3 s budget; a Worker adds build and test cost. |
| S23 | No first-pass "explain" AI task: Finding statements, fixes and conditions come from deterministic templates; only `judge` and Deep Analysis add model text. | Templates satisfy PRD-F-05 and PRD-P-02 with fewer model calls and no extra consent surface. |
| S24 | Inferred Requirements are generated only by `ContractService` (after extraction, on add/accept), skipped when the Contract already has Inferred items; ids `I-D-nn`/`I-M-nn`. Run never generates them. | One owner for Contract content; Runs stay reproducible and never call `infer-responsive`. |
| S25 | Sample Projects never open a consent modal during a Run: Judged items fall back to labelled pre-computed results with a non-blocking "Allow cloud to judge live". | Keeps the 2-click path (PRD-M-13) on any browser while staying honest (PRD-D-22). |
| S26 | `RuntimeValuesSchema`, `Thresholds`, `DEFAULT_RUNTIME_VALUES` live in the kernel; `@fb` only implements `RuntimeConfig`. Kernel tsconfig includes the `DOM` lib for types only. | Features, tests and E2E get defaults without importing Firebase (`SPEC-PERF-04`); `Blob`/`AbortSignal` appear in port signatures. |
| S27 | Build order: step 0 kernel freeze (kernel, module table, skeletons, architecture tests), then 3 parallel workers with disjoint folders (§3.8). | Safe parallel work (PRD-D-14, PRD-R-12). |
| S28 | The demo sample is unbranded: nav placeholder wordmark "Sample Co.", Project name "Sample landing page". | Owner decision under PRD-D-28 (fictional, unnamed sample site). |
| S29 | Build-readiness amendments (2026-11-25), each recorded in its owning row: SPEC-FB-02, SPEC-KERNEL-12, §4.1.3 (`SendList`, `RunSummary`), §3.8, §4.5.1, §10.2 O1, §4.11.2, SPEC-DEMO-05, §4.8.1 (`precomputed` per Run, `rejudge`), §4.9.1 (`applyPrecomputed`), §4.7.1 (`loadPrecomputedExtraction`), SPEC-APP-01 (`cloudUsage`), SPEC-SET-06, §4.1.6, ROADMAP 18, §8.3, §8.1. | Every build task is implementable within the module rules, and the cut list needs no mid-sprint SPEC edit. |
| S30 | **Visual design "Caliper (calmed)"** (owner-approved 2026-11-25; source `design/DESIGN.md`, `design/handoff.md`, tokens in `design/tokens.json`): four hues only (accent blue `#2563EB`/`#60A5FA`, danger, success, `diff` overlay); the `major`, `minor`, `review` hues and all `*-bg` tints removed, severity shown in ink by shape and word (`SPEC-UI-02`, `SPEC-UI-04`); IBM Plex Sans + Plex Mono self-hosted via `@fontsource/*` and precached (§2.2, `SPEC-PWA-03`); radius 3/4/6 px replaces 10 px; no em dash in UI copy (`SPEC-UI-07`); new `ErrorCode` `STORAGE_UNAVAILABLE` (§4.1.5, `SPEC-STORE-04`, §5.4). | The owner asked for fewer colour variations, a non-default typeface and flatter shapes; shape + word keeps severity readable without colour (PRD-P-12); the Projects error state needed a code for an unopenable database. All 64 token pairs pass AA. |
| S31 | `package.json` `overrides` pins `@grpc/grpc-js` to 1.14.7 under `@firebase/firestore`. | Firestore's Node-only gRPC transport carries an advisory that fails `npm audit --omit=dev --audit-level=high`; it is not in the browser bundle (the app never imports Firestore). Remove the override when firebase bumps firestore's `@grpc/grpc-js` range. |
